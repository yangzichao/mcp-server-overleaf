# Install the Claude Desktop Bundle

Claude Desktop installs local MCP servers from a single `.mcpb` file: a zip holding the
server, its locked dependencies, and a `manifest.json` describing what it is. Double-clicking
one opens an install panel. Nothing else is required — no terminal, no Node installation, no
build step.

This is the shortest path for someone who only uses Claude Desktop. Everyone else should use
[`setup`](../README.md#install-with-one-command), which also reaches Claude Code, Codex and
Cursor, and can register several projects at once.

## Install

1. Download
   [mcp-server-overleaf.mcpb](https://github.com/yangzichao/mcp-server-overleaf/releases/latest/download/mcp-server-overleaf.mcpb)
   from the latest release.
2. Double-click it, or drag it onto the Claude Desktop window, or use
   **Settings → Extensions → Advanced settings → Install Extension…**.
3. Fill in the two fields the panel asks for:

   | Field | Where it comes from |
   | --- | --- |
   | Overleaf project address | The browser address bar with the project open, for example `https://www.overleaf.com/project/64a1b2c3d4e5f6a7b8c9d0e1`. The bundle takes the id out of the URL itself. |
   | Overleaf Git token | <https://www.overleaf.com/user/settings> under Git integration. Claude Desktop stores it in the operating system keychain and passes it to the server as an environment variable. |

4. Enable the extension and ask Claude to list the files in the project.

A read-only share link is not a project address; open the project and copy the address bar
instead. The token needs an Overleaf plan that includes Git integration, and Overleaf expires
these tokens after one year.

## What is inside

```
mcp-server-overleaf.mcpb
├── manifest.json        generated from package.json and the server's own tool list
├── icon.png             generated by scripts/mcpb/renderBundleIcon.mjs
└── server/
    ├── dist/            the compiled server, unpacked from the npm tarball
    ├── package.json
    ├── npm-shrinkwrap.json
    └── node_modules/    runtime dependencies only, installed with --omit=dev
```

The `server/` directory is the exact tarball npm publishes for the same version, so the
bundle and `npx mcp-server-overleaf` run identical code. The build refuses to continue if a
development dependency or a `.env` file reaches the staging directory.

The bundle is macOS and Windows only, because that is where Claude Desktop runs. Node is not
listed as a requirement because Claude Desktop ships its own.

## One project per installation

The install panel asks for a single project, which the server registers under the name
`default`. To work with several projects, use `setup` instead: it writes a `projects.json`
holding one entry per project, and the same server reads it.

## Build it yourself

```bash
npm ci
npm run mcpb:build
```

The result is `build/mcpb/mcp-server-overleaf-<version>.mcpb`. The build packs the npm
tarball, installs runtime dependencies into the staging directory, starts the staged server
and reads its tool list back over stdio, writes the manifest from that list, validates the
manifest against the MCPB schema, packs the archive, then unpacks it again and runs the entry
point the manifest names. A manifest can therefore never describe a tool the bundle does not
have.

The same build runs in CI on every push, and the release workflow attaches its output to the
GitHub release after npm has accepted the same server code.

## Update and remove

Installing a newer `.mcpb` over an existing extension replaces it; Claude Desktop keeps the
values you entered. Removing the extension in **Settings → Extensions** stops the server and
forgets the token, but leaves the local clone in `~/.overleaf-mcp/projects`. Delete that
directory to remove the copies of your papers, and revoke the token in Overleaf.

## When something does not work

| Symptom | What to check |
| --- | --- |
| The extension installs but exposes no tools | Fully quit and reopen Claude Desktop. On macOS its server log is `~/Library/Logs/Claude/mcp-server-mcp-server-overleaf.log`. |
| Every tool fails with an Overleaf error | The token may have expired, or the account's plan may not include Git integration. Generate a new token and reinstall. |
| `compile_project` fails while other tools work | Compilation needs `latexmk` and a TeX distribution on the machine. The bundle does not carry TeX. |
| The project address is rejected | A share link has no `/project/<id>` in it. Open the project and copy the address bar. |
